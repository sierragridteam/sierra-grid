# Grid round 2: objective data inventory

Audited 2026-11-07 Pacific / 2026-11-08 UTC. Read-only examination of data commit `03fa460e50430a312a6947a9ba2195ce0d32c7b9` and SDK commit `ae022215a8955ecac14a349e26e55aa14b63e8f0` (package 0.1.1), plus public GET aggregate probes. No old Grid candidates examined; no production records captured in this note. Counts below are observations, not fixtures or promises.

## Client and coverage contract

Use `createSierraClient({baseUrl: 'https://data.sierragridteam.org'})` explicitly. The SDK defaults to that origin, validates JSON with generated Zod, requests OBJECT geometry, supports cancellation/timeouts, conditional GET and structured/plain HTTP errors. All public data routes in the current canonical OpenAPI have facade methods; no blocking missing endpoint identified. Use SDK 0.1.1 and design system 0.5.1 as frozen competition versions. Raw ingest and MCP are not data-browser requirements. Do not call writes or enrichment.

Type-safe query values use generated string enums: event layers `WILDFIRE`, `EVACUATION`, `WEATHER_ALERT`, `EARTHQUAKE`, `ROAD_INCIDENT`, `POWER`, `MESH`, `BURN_STATUS`; statuses `ACTIVE`, `SCHEDULED`, `RESOLVED`, `EXPIRED`; severities `INFO`, `MINOR`, `MODERATE`, `SEVERE`, `EXTREME`. Map layer arguments are lowercase slugs (not event enums); notably MESH events map to `mesh_node`. Use arrays for repeated layer/status filters. API query keys are camelCase, not snake_case; server compatibility aliases do not imply the facade types accept aliases. The SDK returns `ApiResult`: branch on `notModified` before reading `data`; 304 has no data. Burn enum values are prefixed (`BURN_DAY_YES`, `CALFIRE_PERMIT_REQUIRED`, `BURN_PERMISSION_ALLOWED`); fire-weather state is lowercase (`normal`, `elevated`, `red-flag`).

`listEvents` defaults to ACTIVE plus SCHEDULED, all places/layers/severities. An unscoped first page is neither a regional hazard census nor a complete list. Default page size 50, maximum 200, approximately 3 MiB response budget; **only empty nextPageToken proves completion**. `paginate` has a caller-adjustable maximum of 100 pages and can end at that bound with a continuation token; preserve that incompleteness. Event/history queries accept repeated layers, place slug/id, lifecycle filters (events only), minimum severity and observation-time filters. `listHistory` requires explicit valid `from < to` in the facade, unlike the server's optional window. Windows are half-open and on revision observation time. No total-count endpoint exists. Server taxonomy also accepts reserved `FIRE_WEATHER`, `GAUGE`, `AIR_QUALITY` and `ANNOUNCEMENT` layers, but no stored events currently carry them; these are not available gauge, air-quality or announcement datasets. Fire weather is available through the conditions surface described below.

Current objects, historical revisions, condition measurements, and forecast periods are distinct evidence. `observedAt`, `ingestedAt`, `provenance.fetchedAt`, forecast `issuedAt`, monitor `reportedAt` and server `receivedAt` answer different questions. Integer counters encoded as decimal strings must stay exact; nullable gauges must not turn into zero. Some older weather and power scalars use zero for missing upstream data, so those zeroes are not universally measured zeroes.

## Stored event categories (all supported by SDK event/detail/history methods)

Every event carries stable namespaced id, layer/category, severity INFO–EXTREME, lifecycle SCHEDULED/ACTIVE/RESOLVED/EXPIRED, headline, summary, description, area label, canonical URL, geometry/bbox/centroid, placeIds, provenance, effective/expires/observed/ingested times, revision and enhancement attribution. The one relevant detail block is populated. Geometry can be absent. Full detail is richer than map projections. Source links resolve through canonicalUrl, then provenance.sourceUrl, then source registry homepageUrl; absent direct links are common.

| Category | Facts and relationships available | History and important limits |
| --- | --- | --- |
| WILDFIRE | CAL FIRE incidents and FIRIS perimeters: acres, containment percent, county, cause, hasPerimeter, point or polygon footprint. Namespaces `calfire:` and `firis:` represent source items. | Full snapshots allow acreage/containment/perimeter and lifecycle change tracking. Do not assume records from different sources are a canonical merged fire. Fires can attach to areas/towns by proximity (default 20 km), beyond their boundaries; counties retain geometric attachment. |
| EVACUATION | Cal OES/Genasys zone id, order/warning/advisory/shelter-in-place level, event type, county, zone geometry, source text and effective times. | Full revisions include all-clear transitions. No public people/household census or authoritative event-to-fire foreign key. Source failure is unknown, not zero active orders. |
| WEATHER_ALERT | NWS event name/category; original severity, certainty, urgency, instruction, area description, zone ids, geometry, timing; description and optional AI summary. | Revision timeline and resolved/expired products. Preserve verbatim instructions and attribution; summary is not authority. Fire-weather issued state is separately derived from NWS products. |
| EARTHQUAKE | USGS magnitude, depth km, felt report count, location, time and source URL. | Revisions and historical events. Severity expresses response urgency, not magnitude; no seismic waveform or continuous sensor stream. |
| ROAD_INCIDENT | CHP incidents with log number, impact/duration, metadata and text; Caltrans closure windows with window/district/closure/log ids, route, direction, facility, closure/work type, lane counts, estimated delay, duration, planned start/end, indefinite flag, setup time, start/end labels and coordinates. | Planned windows are SCHEDULED; active closures can overrun planned end. Keep status authoritative. Full revision history; not a historical traffic-speed archive. AI-enhanced fields are declared in enhancement.fields. |
| POWER | PG&E planned/unplanned outages: outage id, cause code, customers affected, crew status, estimated restoration. PSPS: event id/name, time-period slice, Watch/Warning stage, medical-baseline affected count, de-energization start/end, planned all-clear, geometry. | Full revisions support changing footprints/counts/stage. Restoration and all-clear timestamps are estimates, never proof power returned. Zero customer count can mean upstream gave none. No household-level outage lookup or meter readings. |
| BURN_STATUS | One persistent county record, daily air-district burnDay, CAL FIRE seasonal permit/suspension status, pessimistic combined permission, CAL FIRE effective/observed times and land class. Each county links one or more phone lines: id/name/phone, answer, latest machine message/transcript/confidence/call time. | Answers/status transitions create revisions; daily unchanged-answer transcripts/observation timestamps refresh without revisions. Two authorities must permit; unknown/stale never means allowed. Geometry absent; no burn_status map layer. Current tracked counties Calaveras and Tuolumne. |
| MESH | Node public key, role/name, geometry when known, reachability, SNR/RSSI/hop count/gateway observers, advert/device time, server last-heard/last-relayed times; optional operator admin measurements. | Identity/location/reachability changes create revisions; volatile signal/measurement refreshes do not. Most nodes lack admin measurements. Presence does not prove connectivity, and reachability is a monitor's admin-interface verdict. See measurement/topology section below. |

`getEventHistory(id)` and `listHistory({from,to,...})` serve full numbered revision snapshots, including lifecycle transitions. Current attachment joins filter archive rows using an event's **current** place/layer, not historical attachment membership. Event history is not every poll: unchanged content, AI enhancements, fresh signal data, and daily same-answer burn observations do not create revisions. It is not an unlimited reconstruction of the world before the service began collecting.

| Category | Public path and SDK support | Meaningful content and caveats |

Integer units; missing upstream values can be 0. Response lastUpdated is aggregate, not seven independent station timestamps. |

NWS grid-cell source, issuedAt, horizonHours, periods with time/temperature/humidity/wind speed/direction/gust, peak gust/time and minimum humidity. Location whose fetch failed may simply be omitted. | Chain controls | `getMapLayer(place,'chain_control')` | Caltrans merged CWWP2 + KML checkpoints/segments, level, highway, direction, geometry and text including closures. Distinguish confirmed healthy empty from source failure. No event detail/history endpoint for condition feature ids. |
| Message signs | `getMapLayer(place,'message_sign')` | District/sign id, route/direction, in-service flag, blank/unknown/message category, one or two three-line pages preserving empty lines, point geometry. Always INFO context; not summary hazards; no archive. |

All 13 map layers: road_incident, chain_control, road_segment, message_sign, weather_alert, fire_weather, earthquake, wildfire, evacuation, power, mesh_node, mesh_link, camera. Common feature envelope includes id/layer/kind/category, severity/rank, headline/description/summary and AI attribution when present, status/time/area and source. GeoJSON uses [longitude, latitude]. Metadata carries health/fetch information. An empty UNAVAILABLE layer does not mean clear conditions.

## Places, rollups and source health

- `listPlaces`, `getPlace`, `resolvePlace`: id/kind/name/slug, geometry, parentId. Live directory has 20 places: Ebbetts Pass AREA; eight counties (Alpine, Amador, Calaveras, El Dorado, Mariposa, San Joaquin, Stanislaus, Tuolumne); seven TOWN points (Arnold, Bear Valley, Columbia, Dorrington, Murphys, Sonora, Twain Harte); four CORRIDOR lines (three Hwy 4 segments and Angels–Sonora Hwy 49). EVAC_ZONE and SITE enum kinds are reserved but unpopulated. County availability in directory does not guarantee equivalent feed coverage throughout every county.
- Resolution accepts lat/lng or a US address via Census; most-specific places first. Town radius applies to resolving a point, not broad event attachment. Towns are points and cannot act as comprehensive local hazard footprints. Geometry attachments differ from weather bbox filtering and camera proximity.
- `getPlaceSummary`: generated time, place identity, QUIET/WATCH/ACTIVE mode, highest severity/counts/totalActive/top five hazards, nullable activeEvacuations and authority URL; domains fire, evacuation, weather, roads, seismic, power, burn, comms with health/severity/count/headlines. Sources sidecar joins registry ids. Burn and mesh are ambient and excluded from hazard totals/mode/top events. **Road conditions can raise roads severity without raising mode**; condition ids cannot be sent to getEvent.
- `listSources`: feed/reporter kind, attribution/homepage, poll interval, stale/expire policy, success/attempt timestamps, last error and OK/STALE/UNAVAILABLE. Reporters are health-only rows; do not interpret their zero poll interval as failure. `burn-line` reporter and `burnline` data freshness are different. Current-condition services also report their own health; registry is not a complete historical source-uptime ledger.

## Mesh measurements and topology (one domain, not the whole dataset)

`listMeshLinks({window})` returns undirected public-key edges, observations, daysActive, firstSeen/lastSeen and bestSnr; default 72h, request capped at 400 days. Join endpoints to MESH public keys; absence of observed edge is not proof no physical radio path. Place `mesh_link` map additionally includes located in-region nodes and linked one-hop neighbors, marked inRegion. Nodes without geometry cannot be mapped.

`getMeshTelemetry({node,from,to})` returns monitor samples, whole-retained-archive coverage from/to/count, effective request bounds, nullable median cadence, inferred reboot times and truncated flag. Default 24h; 400-day window ceiling; 20,000 samples maximum. Split bounded windows when truncated, never silently chart a complete-looking partial range. Well-formed unmonitored key yields empty 200, not 404.

Admin readings contain reporter/reading/success/attempt times; battery volts/percent and derivation source; temperature, humidity, pressure, noise floor, last SNR/RSSI, TX queue; decimal-string uptime/airtime/RX airtime and packet/flood/direct/duplicate/full/error counters. Gauges nullable; reboot/counter resets matter for deltas. Separate reportedAt (device/monitor clock) from receivedAt. Latest event telemetry is not a substitute for this archive.

## Persistence and deliberately unexposed data

SQLite event proto blobs and numbered revision proto blobs are canonical. Scalar indexes, event-place join and R-tree accelerate queries; they are not extra independent facts. Places and source registry are also persisted. Application caches hold live weather/road/condition/camera data; no public historical series exists for those.

Additional storage: raw mesh reception rows (broker/gateway, heard time, signal, hop hashes and resolved path) retained 48h; daily link rollups configured for two years; mesh activity clocks; admin telemetry (generous roughly annual retention); burn_readings staging stores latest per-line reading and diagnostic receive time. Raw mesh receptions/path-by-packet and daily bucket series have no direct public endpoint: links expose aggregate recency windows only, with a 400-day cap even though configured rollup retention is longer. Staged burn receive diagnostics and every daily same-answer call have no separate public archive. Source last-seen/coalescing bookkeeping and refresh validators are internal. `subscriptions` is anticipated schema, not a usable public subscription service.

Separate relay process/database holds operational gateway/lease/audit/repeater state and sealed credentials. These are not Grid public datasets. Its public `/mesh/relay/api/status` is deliberately sanitized and outside this SDK/data contract; authenticated relay controls/private node traffic are outside the competition scope. Never infer private operational data availability from tables or implementation code.

Public enhancement metadata includes model/time/fields; `enhancementIo=true` can expose stored prompt/response but is unnecessary for ordinary exploration and can be large. It does not justify running new enrichment. Loss of event/revision DB would irreversibly lose history; do not assume current upstream feeds can backfill it.

## Live availability probe

Public GETs around 2026-11-08 05:03 UTC returned: all 15 source rows OK; seven current-weather locations and seven 48-hour forecasts (336 periods); fire-weather normal; four cameras, all with HLS, source OK; four scanner references; 20 places. These are transient aggregate observations, not production fixtures.

A complete five-page default-status walk shortly afterward returned 839 events: 1 ACTIVE wildfire, 3 ACTIVE and 65 SCHEDULED road incidents, 768 ACTIVE mesh nodes and 2 ACTIVE burn records; no current events in the other four categories. This global feed is much broader than the Ebbetts area and is not an all-status historical census. A one-row-per-layer archive probe over `[2026-10-01, 2026-11-08 05:00 UTC)` found history for wildfire, evacuation, weather alerts, roads and power; earthquake returned none in that specific window. The MESH archive request timed out at 45 seconds; remaining archive/map/link/telemetry probes were skipped. No inference of archive emptiness or global count follows from a timeout; detailed coverage for those categories remains runtime-verifiable. In Ebbetts Pass, summary hazard highest severity was MODERATE while roads domain was SEVERE, directly demonstrating the mode/domain distinction. Evacuation source was OK with zero active zones there. Empty current hazard categories do not imply absent historical records.

## Audit sources and acceptance implications

Canonical references: `repos/sierra-data/api/grid/v1/grid.proto`, `api/grid/v1/openapi.json`, `internal/hazards/properties.go`, `internal/gridapi/{mesh.go,mesh_telemetry.go}`, `internal/store/{schema.sql,store.go,AGENTS.md}`, `prefab.yaml`; SDK `packages/typescript/src/index.ts` and generated schemas. No application code changed.

No SDK route omission blocks broad competition. The material constraints are upstream/public-contract limits: no condition/weather/camera history, no raw mesh reception API, no per-day topology endpoint, no public operational relay details, no general total count or global history-coverage metadata. Designs must not invent those datasets. The SDK supports available burn history, forecasts, planned closures, PSPS and reference sources already; these are not mesh-only capabilities. Correctness evaluation should require honest pagination/window bounds, clock meanings, source failures, absent values and authority links across every domain.
